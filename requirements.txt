# =============================================================================
# requirements.txt - the ROOT (Windows / dev-host) environment
# =============================================================================
#
# WHAT THIS FILE IS
#   The repo-root venv is the ONE interpreter the whole desk uses on Windows:
#   scripts/ops/start_all.py, scripts/ops/start_openalgo.py, the FastAPI dashboard,
#   the scheduled tasks, and the OpenAlgo app itself (Eventlet WSGI here, not on
#   a stock venv - see the note at the bottom).
#
# WHAT THIS FILE IS NOT
#   * It does NOT describe the Ubuntu VPS. There, `Servers/install_ubuntu.sh`
#     builds the venv from the upstream `openalgo/requirements.txt` (pinned,
#     generated upstream) and then installs `blue_engine[charts]` plus fastapi/uvicorn. Installing
#     this file there would make a second, conflicting source of truth.
#   * It is NOT a lock file. Floor pins with a deliberate upper cap only where a
#     known break exists. Regenerate exact versions with:
#         .\.venv\Scripts\python.exe -m pip freeze > requirements.lock.txt
#
# HOW IT IS USED
#   Fresh host:
#       python -m venv .venv
#       .\.venv\Scripts\python.exe -m pip install -U pip
#       .\.venv\Scripts\python.exe -m pip install -r requirements.txt
#   scripts/ops/start_all.py --update runs the same command.
#
# PROVENANCE OF EVERY PIN BELOW (verified 2026-10-27, python 3.13.15, this host)
#   Each version was read from the installed distribution metadata, not chosen
#   from memory. Where a package is pinned by an extra in Blue_engine/pyproject
#   the extra is named in the comment, so the two files cannot drift silently.
# =============================================================================

# -----------------------------------------------------------------------------
# 8. RUNTIME THE PLATFORM NEEDS ON WINDOWS THAT UPSTREAM DOES NOT DECLARE
# -----------------------------------------------------------------------------
# WHY THESE ARE HERE AND NOT IN openalgo/requirements.txt
#   The upstream file is generated for the Docker image (gunicorn + eventlet).
#   A native venv installing only that file gets neither, which is why
#   start_openalgo.py must pass `allow_unsafe_werkzeug=True`: Flask-SocketIO has
#   no async server and falls back to Werkzeug. That fallback works for one
#   local user; it is not what the dashboard's live callbacks are tested on.
#   Installing eventlet here gives the app its intended async backend, the same
#   one the VPS runs under gunicorn.
#
#   gunicorn itself is NOT installed on Windows: it needs fcntl. The Windows
#   launcher uses Werkzeug (SOP 2026-10-14, "Known Windows pitfalls").
eventlet==0.41.2
