# Live trading plan (2026-11-20)

Flow stage: Broker connection, live gate, bot run, risk controls
Status: PLANNED. Live is OFF. No broker or OpenAlgo connection was made on 2026-11-20.
Owner: Ravindhu. Written from the code on master `ed512dd` and the config files as they were on 2026-11-20.

This plan says what must be true before live orders are allowed, who decides each item, and how to stop.
Nothing here turns live on. Only the owner can do that, by running the approval step with the typed phrase.

## 1. Rules that do not change

1. Live stays OFF until every gate in section 4 is passed and the owner signs the approval.
2. `config/bot.yaml` must stay `mode: paper`, `live_enabled: false` in every commit until the owner decides to go live.
3. Nobody types the approval phrase on the owner's behalf, and no script writes an approval file for them.
4. Any change to `config/risk_limits.yaml` voids the live approval (its hash no longer matches). The approval must be redone after any such change.
5. Every change is committed with the Co-Authored-By and Claude-Session trailer lines, and the full test suite is run first.

## 4. Gates, in order

### Gate 0: owner inputs (no code)
- Set B1 to B6 with real values, in a commit that also records the reason. Changing `risk_limits.yaml` for this reason is allowed, because the approval is made after it.
- Put the OpenAlgo API key in `.env` on the trading machine (never in git).
- Decide the open items in section 6.

### Gate 1: connect OpenAlgo in analyze mode
- Start OpenAlgo on the trading machine. Set `OPENALGO_URL` (default `http://127.0.0.1:5000`).
- Run `scripts/run/run_strategy_bot_live.py --base-url <OpenAlgo URL>` with `mode: analyze` in `bot.yaml`. Analyze mode places no real orders.
- Pass when: the bot starts, reads the screen, reads bars for MTF, HTF and LTF for every screened symbol, and the audit log (`data/bot_live/audit.jsonl`) shows `screen`, `ladder_order` and `pov_band` events with no `CRITICAL` alert.
- Check the bot is still `mode: paper` before leaving the room. (Analyze and paper both place no real orders.)

### Gate 2: paper soak in market hours
- Run the bot in paper mode for at least 5 full trading sessions (NSE 09:15 to 15:30 IST, Monday to Friday).
- Review the audit log every evening. Each of these must be explained, not just counted:
  - `tree_refused`: which touch, why (no decision, a refusal, or a stale bar).
  - `tree_missing` and `tree_no_allocation`: should be rare. Any occurrence needs a cause.
  - `ladder_clamp`: planned shares cut by a cap. Carried shares must show up on the next order.
  - `pov_band_fallback` and `pov_buyer_fallback`: how often the VWAP and buyer-share inputs were missing.
  - `partial_fill_booked` and any `partial` fault: check against the paper broker.
  - `stop_moved` and `stop_placed`: every stop move must have a matching broker stop update.
  - `cycle_skipped`, `entries_blocked`, `positions_unmanaged`: must be zero, or explained.
- Pass when: 5 sessions with no unexplained CRITICAL alert, no fault left open at the end of a session, every open position has a matching stop, and P&L matches the book.

### Gate 3: gate and drill checks (no real orders)
- Run the tests that cover the live gate and the approval:
  `pytest src/quant/tests/test_live_approval.py src/quant/tests/test_run_live_gate.py src/quant/tests/test_live_hardening_2026_11_15.py src/quant/tests/test_strategy_bot_cycle.py tests/unit/test_cycle.py tests/unit/test_cons_touch.py tests/unit/test_risk_tree.py tests/unit/test_setup_store.py`
- Kill-switch drill: trip the kill switch (`data/bot_live/kill.json`) during a paper session. Confirm: no new entries, existing stops still managed, and the bot logs the halt. Reset it and confirm entries resume only after the owner clears it.
- Stop-placement drill: place one stop on a paper position and confirm `_sync_broker_stop` updates it when the trail moves.
- Pass when: every test above passes, and both drills are logged.

### Gate 4: owner approval
- The owner runs `scripts/ops/approve_live.py --approver "<full name>" --reason "<why>"` and types the exact phrase `I APPROVE LIVE TRADING` when asked.
- The approval records the SHA-256 of `risk_limits.yaml`. It is valid for 30 days (`MAX_AGE_DAYS`). It is void if `risk_limits.yaml` changes.
- Pass when: `check_approval` returns valid for the current `risk_limits.yaml`.

### Gate 5: first live session (smallest size)
- Before the session, the owner sets the smallest safe values: `max_order_quantity`, `max_order_notional` and `max_capital_inr` at a level they accept for a first week. Gate 4 must then be redone, because `risk_limits.yaml` changed.
- Set `live_enabled: true` and `mode: live` in one commit, with the owner's name and the approval hash in the commit message.
- Run only the first session with the owner watching the audit log and the broker screen.
- Stop the session at once on any stop-out that is not explained by the logic, any CRITICAL alert, or any mismatch between the bot's book and the broker.

### Gate 6: scale-up
- Owner decision after at least 5 live sessions with no unexplained event. Raise caps in small steps, redoing Gate 4 each time the limits file changes.

## 5. Stop conditions (any one stops live trading for the day)

- A CRITICAL alert that is not cleared within the session.
- `partial` fault open at session end, or a broker stop that does not match the bot's stop.
- Daily loss budget reached (the kill switch trips on the 20,000 INR daily cap).
- A position with no broker stop, or `positions_unmanaged` in the log.
- The data source is not approved, or the feed is missing for a held symbol.
- Any unexplained stop-out, or a P&L that does not match the book.

## 7. Rollback and emergency stop

1. Stop new entries: set `live_enabled: false` and `mode: paper` in `bot.yaml`, and commit it. Or trip the kill switch file `data/bot_live/kill.json`.
2. Revoke the approval: `scripts/ops/approve_live.py --revoke`.
3. Open positions stay at the broker with their SL-M stops. Check each one by hand against the broker screen. Do not assume the bot has closed them.
4. Record what happened in the audit log and in the SOP work log.

Rollback does not close positions. D10 must be settled before Gate 5.

## 9. Risks

- Feed or OpenAlgo outage with an open position. Mitigation: the bot holds the position on the last known bar and alerts, and the owner checks the broker screen.
- Stop not updated at the broker after a trail move. Mitigation: `_sync_broker_stop` after every move, and Gate 3 drill.
- VWAP inputs missing or stale, which changes slice size. Mitigation: fallbacks are logged and reviewed in Gate 2.
- The tree's sizing is new and only tested offline. Mitigation: Gate 2 paper soak, and Gate 5 at the smallest size.
- A partial fill that the broker reports differently from OpenAlgo's `filled_quantity`. Mitigation: check in Gate 2 against the paper broker before live.
